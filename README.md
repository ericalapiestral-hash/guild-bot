# 길드봇

낭만주의 길드 전용 디스코드 봇.

## 기능

**입장 자동역할** — 새로 들어오는 멤버에게 설정해둔 역할을 자동 부여 (봇 계정은 제외)

**빌드 도감** — 노션 "PVE 빌드 도감"을 읽어 슬래시 명령으로 검색. 자동완성으로 빌드 이름을 골라도 되고, 초성(`ㅍㅇㅅㅇ`)이나 띄어쓰기 없이(`파이세인4턴`) 쳐도 찾아준다.

**통계** — 길드 사이트 통계 API를 순위표 임베드로 표시

**서버 로그** — 삭제·수정된 메시지, 음성방 입장·퇴장·이동, 서버 입장·탈퇴를 지정한 채널에 남긴다

**음성 시간** — 음성방에 머문 시간을 사람별로 쌓는다. 주간 기록은 한국시간 월요일 0시에 초기화된다

**채팅 청소** — 최근 메시지를 개수·작성자로 골라 지운다

**읽어주기(TTS)** — 봇이 음성방에 들어와 채팅을 읽어준다. TTS 엔진은 직접 붙인다(아래 참고)

| 명령어 | 설명 | 필요 권한 |
|---|---|---|
| `/파괴신 빌드:파이 세인 4턴` | 파괴신 빌드 찾기 | — |
| `/공성전 요일:수 빌드:…` | 공성전 빌드 찾기 (요일로 먼저 걸러내기 가능) | — |
| `/통계 공성전 [요일] [주차]` | 공성전 순위표 | — |
| `/통계 파괴신 [시즌]` | 파괴신 순위표 | — |
| `/음성 시간 [멤버]` | 음성방 체류시간 (이번 주 · 전체) | — |
| `/음성 순위 [기간]` | 음성방 체류시간 순위 | — |
| `/읽어줘 [내용]` | 음성방에 들어와 그 방 채팅 읽어주기 | — |
| `/그만 [건너뛰기만]` | 읽어주기 멈추고 나가기 | — |
| `/읽기상태` | 지금 어떤 상태인지 보기 | — |
| `/청소 개수 [멤버] [사유]` | 최근 메시지 지우기 (최대 1000개) | 메시지 관리 |
| `/로그설정 설정\|해제\|확인` | 로그 채널 관리 | 서버 관리 |
| `/빌드갱신` | 노션 도감을 다시 읽어오기 | 서버 관리 |
| `/자동역할 설정\|해제\|확인` | 입장 자동역할 관리 | 역할 관리 |

## 설정

`.env.example`을 복사해 `.env`를 만들고 값을 채운다.

```
npm install
npm start        # 봇 실행 (슬래시 명령은 시작할 때 자동 등록됨)
```

### 디스코드

1. [개발자 포털](https://discord.com/developers/applications) → **Bot** 탭에서 토큰 발급
2. 같은 탭에서 인텐트 2개 켜기
   - **Server Members Intent** — 입장 자동역할, 입퇴장 로그
   - **Message Content Intent** — 삭제·수정된 메시지의 *내용* 로그
     (꺼져 있어도 봇은 돌아간다. 대신 "내용을 알 수 없어요"로만 남는다)
3. **OAuth2 → URL Generator** → `bot` + `applications.commands`, 권한은 `Manage Roles` + `Manage Messages` → 생성된 URL로 초대
4. 서버 설정 → 역할에서 **봇 역할을 부여할 역할들보다 위로** 올리기
5. `/로그설정 설정 채널:#로그` 로 로그 채널 지정

### 로그·음성 시간에 대해

- 음성 체류시간은 `data/voice.json`에 쌓인다. **호스팅을 새로 배포하면 사라질 수 있다.**
- 봇이 꺼져 있는 동안의 통화는 집계되지 않는다. 봇이 켜질 때 이미 통화 중인 사람은 그 시점부터 잡는다.
- 잠수(AFK) 채널은 체류시간에서 뺀다.
- `/청소`는 한 번에 최대 1000개. 디스코드가 100개씩만 지울 수 있어서 내부적으로 나눠 돌린다.
- 디스코드 제약상 **14일이 지난 메시지는 지울 수 없다** (API 자체 제한, 우회 불가). 그 벽에 닿으면 거기서 멈추고 몇 개가 남았는지 알려준다. 고정된 메시지도 건드리지 않는다.
- 채널을 통째로 비워야 하면 청소보다 **채널 복제 후 원본 삭제**가 빠르다 (14일 제한 없음). 필요하면 명령어로 만들 수 있다.

### 노션 도감 연동

1. [app.notion.com/developers/connections](https://app.notion.com/developers/connections) → **내부 연결(Internal)** 생성 → 토큰(`ntn_…`) 복사 → `.env`의 `NOTION_TOKEN`에 넣기
2. **도감 페이지에서 `•••` → 연결(Connections) → 만든 연결 추가**
   이 단계를 빠뜨리면 토큰이 맞아도 404가 난다. 부모 페이지에 추가하면 하위 페이지까지 상속된다.
3. `npm run notion:dump`로 잘 읽히는지 확인 — 인식된 빌드 목록이 출력된다

봇은 시작할 때 한 번, 이후 30분마다 도감을 다시 읽는다. 노션을 고치고 바로 반영하고 싶으면 `/빌드갱신`.

읽어온 결과는 `data/builds.json`에 캐시되어, 노션이 잠깐 막혀도 마지막으로 읽은 내용으로 계속 답한다. (캐시는 봇이 알아서 만들므로 커밋하지 않는다)

#### 도감 페이지 구조

도감은 데이터베이스 3중 구조다. 바깥 데이터베이스의 행이 **묶음**, 그 안 데이터베이스의 행이 **빌드**다.

```
PVE 구분 (DB)
├─ 공성전        → 공성전 리스트 (DB) → 빌드 행들   ← /공성전
├─ 강림 - 파괴신  → 파괴신 구분 (DB)  → 빌드 행들   ← /파괴신
├─ 강림 - 구사황  → (DB)                            (아직 명령어 없음)
└─ 기타          → (DB)                            (아직 명령어 없음)
```

- **카테고리**는 묶음 이름에 `공성전`/`파괴신`이 들어 있으면 붙는다. 없으면 색인에는 남지만 명령어로는 검색되지 않는다.
- **요일**은 빌드 이름 앞부분에서 읽는다 (`월요일 - 루디 / 쥬리, 나타 딜러` → 월). `월·목요일`, `월~수요일` 같은 표기도 인식한다.
- **본문**은 빌드 행 페이지 내용을 통째로 마크다운으로 옮긴다 (헤딩·불릿·콜아웃·표 포함).

헤딩만으로 된 페이지도 예비 경로로 지원한다 — 데이터베이스가 하나도 없으면 헤딩 기준으로 자른다.

### 읽어주기(TTS) 연결

**쓰는 법** — 음성방에 들어가서 `/읽어줘` → 봇이 그 방에 들어온다. 이후 **그 음성방의 채팅창**(음성 채널을 누르면 오른쪽에 열리는 채팅)에 쓰는 글만 읽어준다. 다른 텍스트 채널은 읽지 않는다. `/그만`으로 종료하고, 방에 아무도 안 남거나 5분간 조용하면 알아서 나간다.

읽기 전에 링크·코드블록·이모지는 걷어내고, `ㅋㅋㅋㅋㅋ`처럼 늘인 글자는 줄이고, 150자를 넘으면 자른다. 같은 사람이 연달아 치면 이름을 한 번만 부른다.

봇은 TTS 엔진을 갖고 있지 않다. 두 가지 방법 중 하나로 붙인다.

**① 로컬 프로그램 실행** — TTS 프로그램이 이 컴퓨터에 있을 때

```
# .env
TTS_COMMAND=piper --model ko_KR.onnx --output_file {{out}}
```

`{{out}}`을 쓰면 봇이 임시 파일 경로를 넣어주고 끝난 뒤 그 파일을 읽는다. `{{out}}`이 없으면 표준출력을 오디오로 받는다.
문장은 기본적으로 **표준입력**으로 넘어가고, `{{text}}`를 쓰면 인자로 넘어간다.
셸을 거치지 않으므로 채팅에 명령어를 심어도 실행되지 않는다.

**② HTTP 요청** — TTS가 서버로 떠 있을 때

```
TTS_URL=http://localhost:5000/tts?text={{text}}
# 필요하면
TTS_METHOD=POST
TTS_HEADERS={"Content-Type":"application/json"}
TTS_BODY={"text":"{{text}}","format":"ogg_opus"}
```

> ⚠️ **어느 쪽이든 결과는 반드시 Ogg/Opus(48kHz)여야 한다.**
> MP3나 WAV를 주면 변환기(ffmpeg)가 필요해지는데, 그러면 무료 호스팅 128MB에서 메모리가 터진다.
> 형식이 틀리면 봇이 재생하지 않고 무슨 형식을 받았는지 알려준다.

> **채팅 자동 읽기에는 Message Content Intent가 필요하다.** 꺼져 있으면 `/읽어줘 내용:...`으로 문장을 직접 넣는 것만 된다.
> 봇 초대 권한에 **연결(Connect)·말하기(Speak)** 도 있어야 한다.
>
> 신경망 TTS 모델은 무료 호스팅(128MB)에서 못 돌린다. 모델을 쓰려면 봇을 PC에서 실행하거나, PC에서 TTS를 서버로 띄우고 봇은 ②로 붙여야 한다.

## 오버레이 (PC)

[overlay/](overlay/)에 게임 위에 띄우는 빌드 오버레이가 있다. 도감의 스킬 순서를 3개씩 보여주고, 게임 화면의 턴 숫자를 읽어(OCR) 자동으로 다음 단계로 넘긴다.

```
cd overlay
npm install
npm start
```

- **턴 위치 지정** 버튼(또는 Ctrl+Alt+R)으로 게임에서 턴 숫자가 보이는 곳을 드래그로 감싸면, "자동"을 켰을 때 700ms마다 그 자리를 읽는다. 첫 실행은 인식 엔진 다운로드 때문에 1분쯤 걸린다.
- 단축키: **Ctrl+Alt+O** 숨기기/보이기 · **Ctrl+Alt+L** 클릭 통과(게임 조작 방해 안 함) · **Ctrl+Alt+←→** 수동 이동
- 데이터는 봇이 만드는 `data/builds.json`을 그대로 읽는다. 파일이 갱신되면 오버레이도 자동 반영.
- 게임은 **테두리 없는 창모드**여야 오버레이가 보인다 (전용 전체화면은 안 됨).
- 구사황·기타 묶음도 오버레이에서는 전부 보인다 (봇 명령어와 별개로 도감 파일을 직접 읽으므로).
- 같은 라운드가 두 번 있는 분기 빌드(예: 2라운드 4턴/8턴)는 칩으로 골라서 진행한다.

모바일은 오버레이가 불가(iOS)하거나 제약이 커서(Android), 디스코드 봇 `/파괴신`·`/공성전` 검색으로 커버한다.

## 개발

```
npm test              # 파서·검색 자체 점검
npm run notion:dump   # 노션에서 읽은 원본을 data/notion-dump.md로 저장
npm run deploy        # 슬래시 명령 수동 등록 (보통 필요 없음 — 시작 시 자동)
```

기능 추가는 파일만 놓으면 자동 로드된다.

- **명령어**: `src/commands/`에 `data`(SlashCommandBuilder) + `execute` 내보내기. 자동완성을 쓰면 `autocomplete`도 함께.
- **이벤트**: `src/events/`에 `name`(Events.~) + `execute` 내보내기
- **설정 저장**: `src/store.js`의 `get`/`set` (`config.json`에 저장)
